# Reflection and Synthesis

## Issue Classification

Use these categories:

- SYSTEM: server, timeout, OOM, environment, tool failure.
- EXECUTION: code bug, wrong config, missing manifest, incomplete run.
- EVIDENCE: missing source, metric mismatch, weak trace, cherry-pick risk.
- CLAIM: source binding, verdict calibration, forbidden inference.
- REPORT: unclear scope, missing limitation, misleading summary.
- PLANNING: wrong route, bad budget, missing failure attribution.
- PIPELINE: phase order, handoff, stale state.

Track: FIXED, RECURRING, NEW.

## Recommendation Quality

A good recommendation states what to change, where, why evidence requires it, expected effort, and how to verify the fix.

## Synthesis

When perspectives conflict, choose the interpretation best supported by evidence. Do not average a strong false-accusation concern into a mild wording issue.

End with prioritized next actions: fix report, rerun/debug, narrow verdict, ask user, or stop with limitations.
